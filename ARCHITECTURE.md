# SLINGWRECK — architecture

**Revision 1. Frozen.** Changing anything in this document is a deliberate act that
requires bumping the revision and re-verifying every gate in `docs/BUILD_PLAN.md`.

Re-verify with `npm run check`.

## 1. Hard constraints

| Constraint | Why |
| --- | --- |
| Vanilla JavaScript. No dependencies in the shipped bundle, no build step, no bundler, no TypeScript. | House style, matches `bop`, `overpop`, `tree`, `isuck`. |
| **ES modules**, one `<script type="module">` entry. | The relay and the Node tools must `import` the exact same `physics.js` and `sim.js` the browser runs. This is the whole architecture. It costs the ability to run from `file://`, which is an acceptable trade here — `isuck` and `overpop` pay the opposite trade for the opposite reason. |
| All paths relative. Never `/physics.js`, always `./physics.js`. | Served at a domain root today, but the guard also frames it, and dev servers vary. |
| All art drawn procedurally on canvas 2D. All audio synthesised in WebAudio. | Zero asset files. The only PNGs in the repo are marketing screenshots generated by Playwright from the real game. |
| `physics.js` and `sim.js` import nothing but each other and `data.js`. | They run in three hosts: browser, Durable Object, Node. |
| Every new module must be listed in `docs/FILE-PLAN.json` with a line budget before it is written. | An unplanned file is how a 900-line renderer becomes a 3000-line renderer. |
| No `innerHTML` with interpolated data. No `eval`. | Trivially avoidable. |

## 2. Module boundaries

```
data.js  ──────────────┐
                       ├──> physics.js ──> sim.js ──┬──> game.js ──> render.js, audio.js, net.js, build.js
                       │                            ├──> worker.js
                       └────────────────────────────┴──> tools/*.mjs
```

Rules:

- **`data.js` is leaf.** It imports nothing. It holds `TUNE`, `MATERIALS`, `SHAPES`,
  `AMMO`, `PIGS`, `CARDS` and the star thresholds. Every number that the client, the
  relay and the harness must agree on lives here and nowhere else.
- **`physics.js` knows nothing about the game.** It has bodies, contacts, a solver,
  an island sleeper and a raycast. It does not know what a pig is. If a function
  mentions "pig" or "score" it is in the wrong file.
- **`sim.js` knows nothing about the presentation.** No canvas, no `document`, no
  `window`, no `AudioContext`, no `WebSocket`, no `Date`, no `performance`, no
  `Math.random`. It emits an *event list* each step (`{kind:'shatter', x, y, mat}`,
  `{kind:'pop', pig}`, `{kind:'boom', x, y, r}`) which `render.js` and `audio.js`
  consume. It never calls them.
- **`render.js` and `audio.js` are pure sinks.** They read world state and the event
  list. They never write to the world.
- **`build.js` produces blueprints, never live worlds.** A blueprint is plain data.
  `sim.js` is the only thing that turns a blueprint into bodies.

## 3. Determinism contract

The relay audits clients by replaying their shots. That only works if the same
inputs produce bit-identical output in V8, SpiderMonkey and JavaScriptCore.

IEEE-754 doubles make `+ - * /` and `Math.sqrt` exactly specified and therefore
portable. **Nothing else is.** `Math.sin`, `Math.cos`, `Math.tan`, `Math.atan2`,
`Math.pow`, `Math.exp`, `Math.log`, `Math.hypot` and `Math.cbrt` are implementation
defined and *do* differ in the last bits between engines.

Therefore, inside `physics.js` and `sim.js`:

- **Banned:** every `Math.*` function except `Math.sqrt`, `Math.abs`, `Math.min`,
  `Math.max`, `Math.floor`, `Math.ceil`, `Math.round`, `Math.sign`. Also banned:
  `Math.random`, `Date`, `performance`, `Intl`, and iteration over any `Set` or `Map`
  whose insertion order depends on a hash.
- **Rotation is stored as `(c, s)`, not as an angle.** Integration is
  `c' = c - s*w*dt`, `s' = s + c*w*dt`, then renormalise by `1/sqrt(c*c + s*s)`.
  Arithmetic and one `sqrt` — portable, and it removes trigonometry from the hot loop
  entirely.
- Where an angle genuinely is needed (aim vectors from the UI, the 15° rotation snap
  in the editor) it is **converted to `(c, s)` at the boundary** by the caller and
  crosses into the sim as a unit vector. `game.js` may use `Math.atan2`; `sim.js`
  may not.
- Any approximation the sim does need — a falloff curve, a soft clamp — is a
  polynomial in `data.js`, not a library call.
- Randomness comes only from a seeded xorshift `rng(seed)` in `physics.js`, threaded
  explicitly. `render.js` and `audio.js` may use `Math.random` freely; nothing they
  do feeds back.
- Accumulation order is fixed. Bodies are solved in stable id order, contacts in
  generation order. No sorting by a float key without a stable id tiebreak.

**This is verified, not assumed.** `npm run test:determinism` runs the same seeded
scenario in Node, Chromium, Firefox and WebKit and compares a digest of every body
pose after 1800 steps. It is a phase 1 gate and it stays in CI. If it ever fails,
the audit model in §5 degrades to `VALIDATE=lenient` (bounds and plausibility checks
only) rather than the whole design collapsing — see `docs/BUILD_PLAN.md` P6.

## 4. The world

- **Y is up.** The renderer flips. The sim never thinks about screen space.
- **One world unit is one standard cube edge.** A fortress plot is 24 wide and 16
  tall with its ground at `y = 0` and its left edge at `x = 0`. The slingshot pivot
  sits at `x = -16, y = 2.4`. The camera frames `x ∈ [-18, 26]` and scales to
  whatever canvas it is handed, so a phone and a desktop see exactly the same shot.
- **Fixed timestep, `1/60`, never varies.** Rendering is decoupled; a slow device
  draws fewer frames and simulates the same. The accumulator caps at 4 steps of
  catch-up so a background tab cannot fast-forward a round.
- Step order: `integrate → broadphase → narrowphase → warmStart → solveVelocity ×N →
  integratePositions → solvePosition ×M → damage → explosions → sleep → cull`.

## 5. Netcode model

The structural fact that makes this cheap: **the two players' worlds never interact.**
You shoot at their fortress in your simulation, they shoot at yours in theirs.

| Phase | Authority | Traffic |
| --- | --- | --- |
| Build | **Relay.** It validates the blueprint against budget and legality, settles it under gravity itself, and sends the settled result to the opponent. | one blueprint each, on lock-in |
| Siege | **The attacking client**, audited. It runs the opponent's fortress locally and reports shots and score. | shots as they happen; an 8 Hz preview frame |
| Draft | **Relay.** It rolls the three cards from the match seed and applies the pick. | one pick |

The audit: the `SiegeRoom` Durable Object replays each reported shot through the
same `sim.js`, spread across real time so it never blocks, and compares a score
digest at each shot boundary. Divergence past tolerance forfeits the round and is
logged. Wall-clock plausibility (shots cannot arrive faster than the sim allows) and
hard bounds (a score above the theoretical maximum for that fortress) are checked
unconditionally, even in lenient mode.

The corner preview is deliberately *not* the audit stream. It is a lossy 8 Hz frame
of quantised block poses, alive-pig flags, score and ammo remaining, sized to render
at 260×150 px. It is allowed to be wrong by a frame; nothing depends on it.

Reconnect during a siege round is allowed — unlike a brawler, the world is
reconstructible from `(blueprint, seed, shot log)`, all of which the relay holds. A
reconnecting client is handed the log and fast-forwards.

## 6. Naming

- Files kebab-case. Identifiers camelCase. Module constants `SCREAMING_SNAKE`.
  Classes `PascalCase`. Node tools are `.mjs`.
- Ids in `data.js` are short lowercase strings (`'wood'`, `'lob'`, `'king'`,
  `'flak-hog'`) and are **wire format** — renaming one is a breaking change.
- 2-space indent, single quotes, semicolons.
- Comments explain *why*, and name the alternative that failed. A comment that
  restates the line above it is deleted on sight.

## 7. Cache busting

Module specifiers and the stylesheet carry `?v=YYYYMMDD-N`, matching `bop` and
`taming`. Because that stamp has to agree across every importing file at once,
`tools/stamp.mjs` rewrites it everywhere and `npm run check` fails if the stamps
disagree. Hand-editing them is how `bop` nearly shipped a half-updated bundle.
