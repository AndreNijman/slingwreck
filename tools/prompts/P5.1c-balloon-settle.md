One narrow fix in `build.js`: `settleTest` fails on any pig that is supposed to move.

## Reproduction

```js
const bp = { v: 1, blocks: [['cube','wood',10,0.5,0]],
             pigs: [['runt', 6, 0.3, 0], ['zep', 14, 3, 0]] };
settleTest(bp, {});
// runt only  -> ok true,  maxMove 0.00000
// runt + zep -> ok false, maxMove 0.60000, moved ["pig:1"]
```

A Zeppelin Hog drifts ±1.5 units over 5 seconds because that is its authored trait. Over
the 3-second settle it moves 0.6, `settleTest` calls that a collapse, and the blueprint is
rejected.

Episode 3 introduces the Zeppelin Hog. As it stands **every level containing one would
fail `tools/level-export.mjs --lint`**, and so would every Siege fortress using the
`airlift` card, which puts the King on a balloon.

The last report said the Zeppelin was "excluded from that movement figure". It is not
excluded in `settleTest` — that is where it matters.

## The fix

Exclude a body from the **movement** check when it is *declared* to move, and only then:

- a pig whose `traits.balloon` is set, and its balloon body,
- a King carrying the `airlift` effect, and its balloon body.

Key point: exclude by **reason**, from the trait data, not by raising a tolerance and not
by special-casing the id `zep`. A future floating pig should be covered automatically, and
a pig that is *not* declared to move must still be held to the strict tolerance.

Everything else about these pigs is still checked. In particular they must still be
**alive** at the end of the settle — a balloon pig that starts inside a block, or one
whose balloon is crushed on the first step, is a broken placement and must still be
rejected. Only the movement assertion is waived.

Also: a balloon pig must still be inside the plot at the end of its drift, not just at
placement. A zep placed 1.2 units from the plot edge with a 1.5-unit drift range leaves
the plot, and that should fail validation with `out-of-bounds` rather than being
discovered at play time. Check the placement against the **drift extremes**, not the
resting position.

## Acceptance

1. The reproduction above: `runt + zep` returns `ok true`, and the report says which
   bodies were exempt and why.
2. A zep placed so its drift crosses the plot edge fails `validate` with
   `out-of-bounds`.
3. A zep placed inside a block still fails — either `overlap`, or dead on settle. It must
   not pass just because movement is exempt.
4. A non-balloon pig moving 0.6 still fails, unchanged.
5. Add all four as assertions to `tools/editor-test.mjs`.
6. `node tools/level-export.mjs --lint`, `node tools/editor-test.mjs`,
   `node tools/check.mjs`, `npm test` all pass.
