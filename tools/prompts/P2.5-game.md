## 1. The fixed-step accumulator, and the interpolation trap

```js
const elapsed = Math.min(250, now - last);
accumulator += elapsed / 1000;
let steps = 0;
while (accumulator >= TUNE.step && steps < TUNE.catchUpSteps) {
  capturePose(renderer, round);      // BEFORE the step, every step
  events = stepRound(round, TUNE.step);
  pushEvents(renderer, events);
  accumulator -= TUNE.step;
  steps++;
}
draw(renderer, round, camera, accumulator / TUNE.step, aim);
```

The `capturePose` call is the point. `render.js` currently caches the previous pose
only at draw time, so on any frame that runs two or more simulation steps it
interpolates from a pose two steps old and the whole world visibly lags and jitters
under load — worst on exactly the slow devices that need it most. **Add
`export function capturePose(r, round)` to `render.js`** that snapshots every body's
`x, y, c, s` into the renderer's cache, and have `draw` interpolate from that snapshot
rather than managing its own. That is the only change you may make to `render.js`.

Cap the accumulator so a backgrounded tab cannot fast-forward a round, and never let
`dt` vary — the simulation must stay bit-reproducible.

## 2. Camera behaviour

Three states, driven by round phase, using the `frameRect` and `panTo` that already
exist:

- **aiming** — frame the slingshot and the near part of the plot, so the player sees
  what they are pulling against. Zoom out smoothly if the drag is at full stretch.
- **flying** — follow the critter, clamped inside `viewMinX..viewMaxX`, leading it
  slightly in its direction of travel so the player sees where it is going rather than
  where it has been.
- **settling and aiming again** — frame the fortress plot.

Transitions use `panTo`, never a hard cut. Mouse wheel and pinch adjust a user zoom
offset that survives the automatic framing.

## 3. Input

- **Drag to aim.** Press within a generous radius of the sling pouch — make the grab
  radius forgiving, roughly 2 world units, because a tight one feels broken on touch.
  Drag anywhere after that. The draw vector is clamped to `TUNE.slingRadius`. Release
  fires. Dragging *back and down* must launch *forward and up*: the launch is opposite
  the draw. Verify that on screen rather than assuming it.
- The aim object handed to `draw` is `{ active, dx, dy }` matching what `drawSlingshot`
  already expects.
- **Tap or `Space` while flying** triggers the ability. In P2 only `nib` exists, which
  has none, so show the tap affordance but expect nothing to happen; do not fake it.
- `R` restarts, `M` mutes, `Esc` returns to the menu.
- Touch: identical drag, plus a large invisible hit area. No hover-only affordances
  anywhere.
- Pointer Events, not separate mouse and touch handlers.

## 4. Screens

Semantic sections in `index.html`, toggled by a `hidden` attribute, in the style of the
other games in this family: a title screen, the in-round HUD, and a round-over panel.

- **Title:** the game name, a one-line description, a Play button. Draw a small
  animated scene behind it if it is cheap; skip it if it is not.
- **HUD:** remaining critters shown as actual drawn critter heads rather than a number,
  the score, and a restart button. Keep it out of the play area — the fortress sits on
  the right of the frame, so the HUD belongs top-left.
- **Round over:** won or lost, the score, stars earned (campaign scoring is already in
  `sim.js`), Retry and Next buttons. Next may be disabled in the slice.

One hardcoded level for now, as a `const SLICE_LEVEL` blueprint in `game.js` with a
comment saying P5 moves it into `levels.js`. Make it a genuinely good level: a
two-tower structure with a wood frame, glass upper storey, a stone base, one TNT crate
placed so a good shot chains, and three pigs including one that is only reachable by
collapsing something. It is the first thing anyone will ever play.

## 5. style.css

The renderer owns the game world; CSS owns the shell around it. Match the storybook
palette — import nothing, no webfonts, use a system stack. Warm parchment surfaces,
ink text, generous spacing, chunky rounded buttons with a visible press state. Full
viewport canvas, `viewport-fit=cover`, safe-area insets respected, works in portrait.
No pure black or pure white.

## 6. index.html

Follow the family conventions: `lang="en"`, a real `<title>` and description, canonical
URL `https://slingwreck.andrenijman.com/`, Open Graph and Twitter card tags pointing at
`og-image.png`, `theme-color`, and an inline data-URI SVG favicon drawn as a small
slingshot or a pig. Module script entry with a cache stamp.

## 7. tools/stamp.mjs

`ARCHITECTURE.md` §7 requires every module specifier and the stylesheet to carry
`?v=YYYYMMDD-N`, and requires them all to agree. `tools/check.mjs` already fails when
they disagree. Write the tool that sets them: it rewrites the stamp across
`index.html` and every module import in every source file in one pass, takes an
optional explicit stamp argument, otherwise uses today's date and bumps the serial if
today's date is already in use. Hand-editing these is how `bop` nearly shipped a
half-updated bundle.

## Quality bar

- No console errors, no page errors, no failed requests. `tools/smoke.mjs` will fail
  the build on any of them in the next task.
- Runs at 60 fps on a mid-range phone. Do not allocate per frame in the render path.
- Keyboard reachable and screen-reader sane: real `<button>` elements, labels on
  controls, focus visible, `aria-live` on the round-over announcement.
- `game.js` budget 1300 lines.
