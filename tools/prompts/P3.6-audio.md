Write `audio.js` for SLINGWRECK. Read `ARCHITECTURE.md` §2, `sim.js` (for the event
list), `render.js` (for how a pure sink consumes those events), and `game.js` (for the
existing mute state, which `M` already toggles).

`audio.js` is a **pure sink**, exactly like `render.js`: it reads the sim event list and
never writes to the world. **All sound is synthesised. There are no audio files and there
never will be** — that is a house rule across this whole family of games.

## Sound direction: warm, woody, slightly lo-fi

Match the art. The visual register is a faded 1970s picture book; the audio register is
the same — **wooden, soft-edged, a bit dusty**. Not a synthesiser demo.

Concretely, avoid what a default implementation reaches for: no bare sine bleeps, no
sawtooth zaps, no long reverb tails, nothing that sounds like a UI notification. Put a
gentle lowpass across the whole bus, roll off above about 6 kHz, and let almost every
sound be short.

Suggested recipes — adjust by ear, and say what you changed:

| event | recipe |
| --- | --- |
| `launch` | a short filtered-noise *thwip* with a fast downward pitch sweep, plus a soft wooden knock |
| `hit` | a band-passed noise thump, centre frequency and gain scaled by the impulse, with the material tinting the filter — wood mid, stone low, iron a touch of metallic ring |
| `shatter` (glass) | three or four very short high noise bursts at slightly different pitches, tight decay. Bright but not piercing |
| `crumble` (sand) | a longer, darker noise burst with a soft attack |
| `stone-split` | a low crack plus a short rumble |
| `boom` | a low sine thump for the body, band-limited noise for the blast, and a fast-decaying lowpass sweep. No long tail |
| `pop` (pig) | a short, comic, slightly pitched puff — the most characterful sound in the game, and the one the player earns. Vary its pitch slightly per pig type so a King pop reads bigger |
| `balloon-pop` | a tight rubbery snap, higher than a pig pop |
| `spring-launch` | a quick upward pitch bend, boinging but restrained |
| `repair` (Sarge) | a small friendly two-note woodblock figure |
| `ability` | one recognisable sound per ability, keyed off the ability id, so a player learns them by ear |
| `won` / `lost` | a short three-note warm phrase, major for won, flattened for lost. Under a second |
| `settled` | nothing. Silence is the correct sound for "the world stopped moving" |

## Hard requirements

1. **Create the `AudioContext` lazily, on the first user gesture**, never at module load.
   Every browser blocks it otherwise and Safari is the strictest. Expose
   `unlock(a)` for `game.js` to call from the Play button handler, and make every play
   function a no-op until then rather than throwing.
2. **Voice limiting.** Cap concurrent voices at about 16 and drop the quietest when over.
   A collapsing tower emits dozens of events in a few frames.
3. **Coalescing.** Identical event kinds arriving within roughly 30 ms collapse into one
   slightly louder voice. Twenty glass shards from one block is one shatter sound, not
   twenty — twenty is both ugly and a clipping hazard.
4. **A master bus** with a gain stage and a soft limiter or compressor, so a chain of TNT
   cannot clip. Nothing connects straight to the destination.
5. **Respect mute**, and stop cleanly. Muting mid-explosion must not leave a stuck voice.
6. Do not allocate in a hot loop where a pooled node would do, and disconnect finished
   nodes so they can be collected.
7. `audio.js` may use `Math.random` freely — it is a sink and nothing it does feeds back
   into the simulation.

```js
export const EVENT_SOUNDS            // event kind -> handler, exported for the test below
```

## The test that matters

The realistic failure here is not a bad sound, it is a **silent event** — `sim.js` gains
a new event kind, nothing plays for it, and nobody notices for a month.

So: **export `EVENT_KINDS` from `sim.js`** as the authoritative list of every event kind
it can emit, and make `sim.js` use it rather than bare string literals so the two cannot
drift. Then add a check that every kind in `EVENT_KINDS` has an entry in `EVENT_SOUNDS`,
with `settled` explicitly allowed to map to silence — an intentional silence must be
declared as one, not achieved by omission.

Put that check in `tools/check.mjs` next to the existing data invariants, so it runs on
every commit and cannot be skipped.

Also add `audio.js` to the smoke gate's coverage in the sense that matters: the browser
run must still report zero console errors with audio wired up and unlocked. Confirm the
context reaches the `running` state after the Play click, and assert it.

## Acceptance

2. `npm test` — 22 assertions still passing, plus the AudioContext state assertion. Run

3. Demonstrate the coverage check works: temporarily add a fake kind to `EVENT_KINDS`,
