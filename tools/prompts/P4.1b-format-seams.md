## 1. The pig tuple gains a flags field — this is the bug

`fromBlueprint` sets `decoy: false` unconditionally, because `[pigId, x, y]` has nowhere
to put it. The editor's King rule works on the draft and then the information is thrown
away on encode. **A Decoy King would therefore arrive at the opponent as a real King**,
and popping it would end the round — the exact opposite of what the card does.

The Flak Hog has the same problem and it is not yet implemented at all: `data.js` says
`chosenBy: 'builder'`, which means one specific placed pig is marked, and that mark has
to survive the wire too.

Change the pig tuple to `[pigId, x, y, flags]` where `flags` is an integer bitfield:

- bit 0 — decoy
- bit 1 — flak

`flags` is optional on read and defaults to 0, so existing blueprints still decode.
Extend `encode`/`decode`, `toBlueprint`/`fromBlueprint`, `sim.js`'s `instantiate`, and
the validation rules. `king-count` must ignore decoys; `understudy` gates bit 0 and
`flak-hog` gates bit 1, both limited to one pig each.

Add an assertion to `tools/editor-test.mjs` that a decoy and a flak pig **survive a full
encode and decode round trip**, and that a decoy still fails `king-count`. That is the
assertion whose absence let this through.

## 2. Free rotation is removed

The editor is 15° steps only, 24 positions, stored as an integer. `docs/DESIGN.md` §6.2
no longer offers `Shift` for free rotation.

An arbitrary angle cannot be represented in the grid-snapped codec without a second and
much larger format, and 24 positions is ample for a fortress. Remove the free-rotation
path from `build.js` rather than leaving it as a function nobody may call — a capability
that cannot survive serialisation should not exist in the editor at all.

`fromDegrees` in `physics.js` keeps its literal table and stays exactly as it is.

## 3. The settled blueprint is not a wire format, so stop producing one

`settleTest` currently returns a `settledBlueprint`, and you correctly noticed that
settled coordinates are off-grid and will not encode.

The resolution is that **the settled state never crosses the wire.** The relay validates
a blueprint, settles it to confirm it stands and that its pigs survive, and then sends
the **authored** blueprint. Both sides settle it themselves and arrive at the identical
state, because §3 proves the simulation is bit-identical across engines. That is what all
that determinism work was for.

So `settleTest` should return `{ ok, settled, movedPieces, deadPigs }` and **not** a
settled blueprint. If a caller needs the settled world it instantiates the authored
blueprint and steps it — which is what `sim.js` already does. Delete the field rather
than leaving an unencodable object available to be misused in P6.

Add an assertion: the same authored blueprint settled twice, in two separate worlds,
produces identical digests. That is the property the whole scheme now rests on and it
should be pinned here rather than assumed.

## 4. The missing error code

`place` refuses a card-limited piece with `piece-limit`, but the validation table has no
matching code. Add `piece-limit` to `validate` so a blueprint arriving from the wire with
three decoys is rejected with the same reason the editor would have given. Anything the
editor enforces must also be enforced on decode — the editor is a convenience, the
validator is the boundary.
