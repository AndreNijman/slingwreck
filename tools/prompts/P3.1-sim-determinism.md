Extend `tools/determinism-test.mjs` to cover `sim.js`, not just `physics.js`.

## Why this is the first task in P3

The cross-engine gate is the foundation the entire netcode design rests on:
`ARCHITECTURE.md` §5 says the relay audits clients by **replaying their shot log through
`sim.js`** and comparing score digests. If `sim.js` is not bit-portable, that model is
worthless and the anti-cheat silently does nothing.

But the scenario the gate actually runs is 40 pseudo-random bodies dropped under
gravity. It exercises `physics.js` thoroughly and **never calls into `sim.js` at all**.
Launch, impulse damage, threshold arithmetic, directional pig armour, deferred death,
explosion falloff, raycast occlusion and TNT chaining are all unproven across engines.

P3 is about to add eight critter abilities' worth of new arithmetic on top of that. Prove
the existing surface portable first, so that if something does diverge later there is a
known-good baseline to bisect against rather than a whole phase of new code to search.

## What to add

Keep the existing 40-body scenario exactly as it is — it is the pure-solver control and
it must stay comparable across commits. Add a **second** scenario beside it and report
both in the table.

### The sim scenario

Build it in the test file, not in `sim.js`, the same way the existing one lives there.
Drive it entirely from a fixed seed and a fixed shot log so it is reproducible with no
wall clock and no input:

- A blueprint of roughly 30 to 40 blocks covering **every material** in `MATERIALS`,
  including at least three TNT crates positioned so one detonation chains to the others,
  and at least one stone slab placed to shield something behind it so the raycast
  occlusion path is exercised.
- Every pig type in `PIGS`, including the King, and including a `helm` and a `tusk`
  placed so their directional armour actually receives hits from both the armoured and
  unarmoured sides. Armour that is never tested from both sides is not tested.
- A bag of `nib` critters — the other abilities do not exist yet — and a shot log of
  about six shots with hand-chosen draw vectors that between them hit the front wall,
  arc over the top, and set off the TNT cluster.
- Run it to the end of the log plus enough steps to settle, taking a digest at several
  checkpoints as the existing scenario does.

Digest with `digestRound` where it captures what is needed. If it does not cover block
hp, pig hp, dead flags and the score, extend the digest so it does — those are precisely
the values the relay compares, so a digest that omits them proves the wrong thing. Hash
raw IEEE-754 bits, never formatted numbers, for the reason already written in
`ARCHITECTURE.md` §3.

### Reporting

Print two tables, labelled `physics` and `sim`, each engine against its checkpoints.
Fail loudly and specifically on the first divergence: name the two engines, the
checkpoint, and the first body or pig whose values differ. A bare "digests differ" for a
600-body scenario is not actionable.

Keep the existing behaviour of exiting non-zero when fewer than four engines are covered
unless `SKIP_BROWSERS=1`.

## Acceptance

1. `SKIP_BROWSERS=1 node tools/determinism-test.mjs` passes.
2. `npm run test:determinism:all` passes — all four engines, both scenarios.
3. The sim scenario demonstrably exercises the paths it claims to: report the number of
   blocks destroyed, pigs killed, explosions triggered and TNT crates chained. If a
   number is zero the scenario is not testing that path and needs rebuilding, so print
   them and check them rather than assuming.
4. `node tools/check.mjs` passes.

## Style

2-space indent, single quotes, semicolons. Comments explain *why*.

## When done

Report both digest tables, the four exercise counts from acceptance criterion 3, and
whether any engine diverged. Write only `tools/determinism-test.mjs`, plus a `sim.js`
digest extension if one is genuinely needed.
