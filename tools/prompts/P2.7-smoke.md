Write `tools/smoke.mjs` for SLINGWRECK. This is the P2 gate — `npm test` runs it — and
every other game in this family has one that works the same way.

Read `tools/state-shots.mjs` first; it already boots a server and drives the real page,
so reuse its approach rather than inventing a second one.

## What it must do

Boot a static server on an ephemeral port, launch headless Chromium, and play the real
game through the real UI. No importing modules and calling them directly — this test
exists precisely to catch the things unit tests cannot: a missing element, a listener
never attached, a stylesheet that hides the canvas, a module specifier whose cache
stamp went stale.

**Fail on any console error, any page error, and any failed request.** That is the
family convention and it is the single most valuable line in the file. Collect them
all and report every one, rather than throwing on the first.

## The run

1. Load the page. Assert the title screen is visible and the Play button is reachable
   by keyboard.
2. Press Play. Assert the HUD appears and shows the full bag of critters.
3. Drag from the pouch back and **down**, hold, and assert a trajectory preview is
   being drawn before release — read it from the page rather than eyeballing a
   screenshot. Expose whatever minimal hook you need for that on `window`, guarded so
   it is inert in production, or assert on canvas pixels if that is cleaner. Say which
   you chose and why.
4. Release. Assert the phase becomes flying, the bag count drops by one, and the camera
   moves.
5. Wait for the world to settle. Assert the score increased and at least one pig died.
6. Keep firing until the round ends. Assert the result panel appears, announces a win,
   and that its heading receives focus.
7. Press Retry. Assert the round resets: full bag, zero score, structure rebuilt.
8. Reload at a 390×844 portrait viewport with touch emulation, and repeat steps 2 to 5
   with touch events. Portrait is not a nice-to-have here; it is most of the traffic.

Assert **measured values**, not just that things did not throw. Print each check as a
PASS or FAIL line with the number next to the expectation, the way
`tools/physics-test.mjs` and `tools/sim-test.mjs` do, and exit non-zero on any failure.

## Reliability

No fixed `waitForTimeout` as a substitute for a condition — poll for the state you
actually want with a timeout and a clear message on expiry. A flaky gate gets ignored
within a week and then it is worse than no gate.

Keep the whole run under about 90 seconds.

Support `BASE_URL` in the environment so the same test can run against
`https://slingwreck.andrenijman.com` later, skipping the local server when it is set.
That is how the other games run their live checks.

## When done

Run it. Report the PASS lines and the total runtime, and anything you had to expose on
`window` to make an assertion possible. Then run `node tools/check.mjs`.

Write only `tools/smoke.mjs` and, if step 3 needs it, a small guarded test hook in
`game.js`.
