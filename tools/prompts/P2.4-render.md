Write `render.js` for SLINGWRECK. Read `ARCHITECTURE.md` §2 and §4, `data.js`, and
`sim.js` first. `render.js` is a **pure sink**: it reads world state and the sim event
list and never writes to either. It may use `Math.random` and any browser API — the
determinism ban applies only to `physics.js`, `sim.js` and `data.js` — but see the
stability rule below, which matters more than the ban.

## Art direction: chunky storybook

Not a generic cartoon. The target is a **faded children's picture book printed in the
1970s**: warm, dusty, slightly off-register, ink outlines on every shape. Everything is
drawn in code; there are no image assets and there never will be.

Deliberately avoid the default browser-game palette — no `#4A90D9` sky, no `#7ED321`
grass, no pure black, no pure white anywhere in the game world.

### Palette — use exactly these, exported as a `PALETTE` object

```
ink            #2B211C   every outline; a warm near-black, never #000
skyTop         #E8D5B0   warm parchment
skyLow         #F2C79A
hillFar        #A8B89A   dusty sage
hillNear       #8FA383
groundTop      #9C8763   dry earth
groundDeep     #6B5A42
```

Materials — fill, then the darker tone used for that material's texture motif:

```
glass   #A8CFD4 / #6E9BA3   drawn at 0.62 alpha, plus one diagonal highlight streak
wood    #C2874A / #8A5A2B   two or three grain lines along the long axis
stone   #9A9691 / #78746F   a few stable speckles
iron    #6E7681 / #4E545C   one cool highlight band, no texture
tnt     #C4453A / #8E2F27   two cream (#EDD9B6) stencil bands
spring  #D4A32C / #9E7818   a drawn coil along the face
gel     #7FB89E / #588273   0.72 alpha, rounded corners, no texture
sand    #C9B183 / #9A8560   stitch dashes along the seams
```

Pigs are **dusty rose**, not green — `#C98A93` body, `#B06E7B` snout and ears,
`#2B211C` eyes. It still reads instantly as a pig and it is not the association every
other game in this genre reaches for. The King Hog is deeper plum `#9A5F73` with a
brass crown `#D9A441`. Critters are warm red-orange `#D9563F` with a cream `#F3E2C7`
belly patch.

### The four techniques that make it "chunky storybook"

1. **Ink outline on every body.** `lineJoin` and `lineCap` both `'round'`, width scaled
   so it is roughly 2.5 CSS pixels at the default zoom and never thinner than 1.5 or
   thicker than 4 — an outline that scales linearly with zoom looks like a mistake at
   both ends.
2. **A vertical fill gradient** on each body, from the fill colour lightened about 8%
   at the top to the fill colour darkened about 10% at the bottom, in the body's own
   rotated frame so it turns with the body. This is what stops a rectangle looking like
   a rectangle.
3. **Edge wobble.** Offset every polygon corner by up to 1.5% of the body's size. This
   is the single most important detail and it has one hard rule: **the wobble must be
   derived from the body id and be identical every frame.** Use a small integer hash of
   `(body.id, cornerIndex)`, never `Math.random`. A wobble that is re-rolled per frame
   shimmers and looks like a rendering bug, which is exactly what it would be.
4. **Soft shadow.** The body's silhouette redrawn offset down-right by about 0.06 world
   units in ink at 0.12 alpha, before the body itself.

### Damage

Blocks show accumulated damage as **ink cracks**, not colour tinting. Draw
`floor((1 - hp/maxHp) * 5)` short jagged polylines across the face, each seeded from
`(body.id, crackIndex)` so a given block's cracks never move once drawn — they only get
added to. Below 25% hp add a faint ink stipple.

### Background

Sky as a vertical gradient, two parallaxing hill bands as smooth blobby polylines, then
the ground with a darker lip along the top edge. Parallax factors around 0.25 and 0.45.
Ground and hills must be generated from a fixed seed so the scenery is the same every
run of the same level.

### Events

Consume the sim event list for transient effects, each with its own short lifetime:
`shatter` throws a dozen small ink-outlined shards in the material's colours; `pop`
throws a puff of dust rings; `boom` draws an expanding ring plus a brief screen shake;
`hit` puts a small impact star at the point, scaled by impulse. Effects live entirely
in `render.js` state — **never in the world**.

## Required exports

```js
export const PALETTE
export function makeRenderer(canvas)          // owns ctx, DPR, resize, effect state
export function resize(r)                     // devicePixelRatio aware
export function draw(r, round, camera, alpha) // alpha = 0..1 interpolation factor
export function pushEvents(r, events)         // from stepRound
export function worldToScreen(camera, x, y)
export function screenToWorld(camera, sx, sy)
export function makeCamera()                  // frames TUNE.viewMinX..viewMaxX, letterboxed
export function drawPreview(ctx, round, w, h) // the 260x150 siege corner preview, P6 uses it
```

`draw` receives an interpolation `alpha` because `game.js` runs a fixed timestep
accumulator and renders between steps. Keep the previous pose of each body in a cache
inside the renderer keyed by body id and interpolate position, and interpolate the
`(c, s)` pair with a normalised lerp — do **not** convert to an angle and back, that is
both slower and wrong across the wrap.

`drawPreview` is a stripped-down pass: fills and outlines only, no gradients, no
wobble, no texture, no effects. At 260×150 those cost real frame time and are invisible.

## Quality bar

- 60 fps with 120 bodies and effects running. Batch by material where you can: one
  `beginPath` per material for the fills, one for the outlines. Do not set
  `ctx.fillStyle` 120 times per frame if 8 will do.
- No layout thrash: read `canvas.clientWidth` once per resize, not per frame.
- Correct on a HiDPI display and on a phone in portrait.
- Nothing in the game world may be pure black or pure white.
