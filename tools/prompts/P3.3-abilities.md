## Two determinism traps — read these before writing anything

**1. `split` needs a rotation and `Math.cos` is banned.** Rotating a velocity by ±22°
must use a precomputed `(c, s)` pair as a literal, exactly like `fromDegrees` in
`physics.js` does for the editor's snap angles. Add the pair to the `chip` params in
`data.js`:

```
cos 22° = 0.9271838545667874
sin 22° = 0.37460659341591196
```

Rotating `(vx, vy)` by +22° is then `(vx*c - vy*s, vx*s + vy*c)` and by −22° is the
same with `s` negated. Arithmetic only. If you find yourself wanting a general
"rotate by n degrees" helper inside the sim, that is the signal to add another literal
pair, not to reach for trigonometry.

**2. `blink` must not teleport into solid matter.** Raycast from the current position
along the velocity direction for `params.distance`; if something is hit, stop just short
of it. Teleporting a body inside a block leaves the solver to resolve a deep
interpenetration, which it will do by ejecting the critter at high speed in a direction
nobody can predict — and it will do it differently once the contact ordering changes.

## The eight

| id | ability | behaviour |
| --- | --- | --- |
| `chip` | `split` | replace the critter with three bodies at −22°, 0°, +22° from its heading, **each keeping the parent's speed**, each with a third of the parent's mass and a radius scaled to keep density constant. The parent is removed the same step. |
| `wedge` | `accel` | multiply velocity by `speedMultiplier` along the current heading. Do not change direction. |
| `lob` | `boom` | detonate at the current position using the explosion path TNT already uses — radial impulse and damage, linear falloff, raycast occlusion. Reuse it; do not write a second explosion. |
| `pebble` | `drop` | spawn the payload body at the critter's position with the critter's velocity plus `payloadSpeed` downward, and add `recoilSpeed` upward to the critter. The payload is a normal body and does normal impulse damage. |
| `boomer` | `reverse` | negate horizontal velocity, keep vertical. |
| `hulk` | `inflate` | grow the radius from `radius` to `inflatedRadius` over `inflateSeconds`, recomputing mass and inertia from the new area each step so density is preserved. Growing into a neighbour must **push it out**, which is what the card is for; let the position solver do that rather than teleporting anything. |
| `spike` | `harden` | pass through glass without slowing, and deal `stoneDamageMultiplier` damage to stone. |
| `zip` | `blink` | teleport `distance` forward along the velocity direction, keeping speed. See trap 2. |

### `harden` needs one generic addition to physics.js

Passing through glass is **collision filtering**, which is a legitimate solver concept
and not game knowledge. Add a generic filter to `physics.js`: a body may carry a
`pierces` value, and the broadphase skips a pair when one body pierces the other's
`filterTag`. `sim.js` sets `filterTag` from the material id and sets `pierces` on a
hardened Spike. `physics.js` must not learn what "glass" means — it only compares two
opaque values.

A pierced body still takes damage: the damage hook must see the pass-through and apply
it. Decide how — most likely a swept test in `sim.js` for bodies the critter passed
through this step — and say what you chose.

## Rules that apply to all eight

- One tap per critter, ever. Tapping again does nothing and must not throw.
- An ability that spawns bodies must give them ids from the same world counter, so the
  shot log replays identically.
- Every ability emits an event for `render.js` and `audio.js`:
  `{ kind: 'ability', ability, x, y }` at minimum, plus whatever that ability needs.
- No `Math.*` beyond the permitted list. `tools/check.mjs` enforces it.
- Abilities are triggered from the shot log's `tapStep`, so a replay reproduces them
  exactly.

## Tests

Add assertions to `tools/sim-test.mjs`, one per ability, each asserting a **measured
difference between tapping and not tapping** from an identical starting state. Print
both numbers. An ability whose tap does not measurably change the outcome is a bug and
this is the only thing that will catch it.

Then extend the **sim scenario in `tools/determinism-test.mjs`** so its bag contains
every one of the nine critters and its shot log taps each one. New arithmetic in `sim.js`
is exactly what that gate exists to protect, and right now the scenario only fires `nib`.
