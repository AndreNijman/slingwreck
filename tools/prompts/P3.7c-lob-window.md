Fix Lob's unusable timing window. This is a design fix, not a balance tweak.

## The measurement

`node tools/playtest.mjs --sweep` reports the number of tap timings that beat not
tapping at all:

| critter | winning timings |
| --- | --- |
| Spike | 47/47 |
| Hulk | 46/46 |
| Pebble | 32/47 |
| Wedge | 20/47 |
| Boomer | 10/47 |
| Chip | 5/47 |
| Zip | 5/47 |
| **Lob** | **2/46** |

Two frames out of forty-six. About 33 milliseconds. Lob is the genre's most iconic
ability — the thing that detonates — and using it well is currently a coin flip on
reflexes rather than a decision.

## The cause

`tap()` in `sim.js` refuses unless `round.phase === 'flying'`:

```js
if (round.phase !== 'flying' || !round.flying || round.flying.dead) return false;
```

So a Lob can only be detonated in mid-air. Once it touches anything the phase becomes
`settling` and the ability is gone. The only good instant is therefore the frame before
impact, which is exactly the 2/46 the sweep found.

That is wrong for this ability. In this genre you watch the bomb come to rest against the
thing you want gone, *and then* set it off.

## The fix, two parts

### 1. Some abilities remain usable at rest

Add `tappableAtRest` to the ability params in `data.js` and allow `tap()` when the phase
is `settling` and the critter is still alive, for abilities that declare it.

- `boom` (Lob) — **yes.** Land it in the rubble, then detonate.
- `inflate` (Hulk) — **yes.** Wedging into a gap and then expanding is the whole point of
  the card, and at rest is when it is most wedged.
- everything else — **no.** Accelerating or blinking a body that has already stopped is
  not a decision, it is a null action, and offering it would only confuse.

Keep the one-tap-per-critter rule. Keep the shot log recording `tapStep`, so a replay
still reproduces a rest-phase tap exactly.

### 2. Lob gets a fuse

Add `fuseSeconds: 3` to `lob`'s params: if it is never tapped, it detonates three seconds
after its **first contact**. If it never contacts anything, it detonates when it would
otherwise be culled, so a Lob is never simply wasted.

Measure the fuse in fixed steps from the contact, not from wall time, so replay is exact.

Emit the same `boom` event either way — the player should not be able to tell from the
feedback whether the fuse or the tap fired it.

## What this changes about the numbers, and why that is fine

The untapped baseline for Lob will **rise**, because an untapped Lob now explodes instead
of just thudding. Tapping must still be worth doing, and it should be: the fuse fires
three seconds after first contact, by which time the Lob has usually come to rest and
settled somewhere ordinary, whereas a tap lets the player pick the moment of deepest
penetration.

So the fuse is a **floor, not the ceiling**. If after this change the sweep shows that
almost no tap beats the fuse, say so plainly — that would mean the fuse is too good and
should be lengthened, and I would rather know than have it hidden.
