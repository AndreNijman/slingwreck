Write `data.js` for the SLINGWRECK project in this directory. Read these first, they
are the specification and they are authoritative:

- `ARCHITECTURE.md` — especially §2 (module boundaries), §3 (determinism contract) and §6 (naming)
- `docs/DESIGN.md` — every table in it becomes data in this file
- `docs/FILE-PLAN.json` — the `data.js` entry: budget 700 lines, imports nothing

## What data.js is

The single leaf module. It imports nothing. It is imported by the browser client, by
the Cloudflare Worker relay and by Node test harnesses, so it must be a plain ES
module with no environment assumptions whatsoever.

## Exports, exact names

- `TUNE` — the object in DESIGN.md §2.1, plus: `plotW: 24`, `plotH: 16`,
  `slingX: -16`, `slingY: 2.4`, `slingRadius: 1.6`, `viewMinX: -18`, `viewMaxX: 26`,
  `settleTimeout: 6`, `roundSeconds: 180`, `buildSeconds: 90`, `draftSeconds: 25`,
  `winsNeeded: 3`, `maxRounds: 5`, `maxBlocks: 120`, `maxBurialDepth: 5`,
  `gridSnap: 0.5`, `rotSnapDeg: 15`, `previewHz: 8`, `catchUpSteps: 4`.
- `MATERIALS` — keyed by id, from DESIGN.md §2.2. Fields: `id`, `name`, `density`,
  `hp` (per unit area), `thresh`, `frailty`, `cost` (per unit area), `restitution`,
  `friction`, `brittle` (bool), plus the material-specific fields the design calls
  for (`tnt` needs `blastRadius`, `blastImpulse`, `blastDamage`; `spring` needs
  `ammoRestitution`; `gel` needs `absorb`; `sand` needs `chunks`).
  Pick sensible `restitution` and `friction` per material and put a one-line comment
  saying why — glass is slippery and bouncy, sand is neither.
- `SHAPES` — keyed by id, from DESIGN.md §2.3. Fields: `id`, `kind` (`'box'`,
  `'circle'` or `'tri'`), `w`, `h` (or `r` for circles), `area`.
  Compute `area` as a literal number, do not call a function at module scope.
- `AMMO` — array in bag order, from DESIGN.md §3. Fields: `id`, `name`, `mass`,
  `radius`, `ability` (a short id string like `'split'`, `'accel'`, `'boom'`,
  `'drop'`, `'reverse'`, `'inflate'`, `'harden'`, `'blink'`, or `null` for `nib`),
  and an `params` object holding that ability's numbers. Also export
  `AMMO_BY_ID`.
- `PIGS` — keyed by id, from DESIGN.md §4. Fields: `id`, `name`, `hp`, `cost`,
  `radius`, `density`, `thresh: 1.0`, `frailty: 1.0`, and a `traits` object for the
  special behaviour (`helm` has `{ armourFrom: 'above', armourFraction: 0.6 }`,
  `tusk` has `{ armourFrom: 'sling', armourFraction: 0.6 }`, `zep` has
  `{ balloon: true, driftRange: 1.5 }`, `sarge` has
  `{ repairEvery: 6, repairFraction: 0.25 }`, `king` has `{ king: true }`).
- `CARDS` — array of all 25 draft cards from DESIGN.md §6.4. Fields: `id`, `name`,
  `tier` (1, 2 or 3), `tierName` (`'reinforce'`, `'dirty'`, `'desperado'`), `text`
  (the player-facing one-liner, copied from the design table), and `effect` — a
  **plain data description** of what it does, never a function. Design the `effect`
  shape yourself but keep it declarative and uniform, for example
  `{ kind: 'unlock', material: 'iron', perRound: 2 }`,
  `{ kind: 'budget', delta: 30 }`, `{ kind: 'pigHp', delta: 1 }`,
  `{ kind: 'previewRate', hz: 0.33 }`. A card whose effect cannot be expressed as
  data is a card that needs redesigning — flag it in a comment rather than exporting
  a function. Also export `CARDS_BY_ID` and `CARDS_BY_TIER`.
- `SCORE` — the siege scoring table from DESIGN.md §6.3 and the campaign scoring
  from §5, as two sub-objects `SCORE.siege` and `SCORE.campaign`.
- `BUDGET` — `{ base: 110, perRound: 25, perDeficit: 15, earlyLockPer10s: 2, winnerBonus: 10 }`.
- `BAG` — `{ base: 6, perRound: 1 }` so bag size is `base + round`.

## Hard rules

- No functions exported except pure lookups built at module scope with plain object
  literals. No `Math.*` calls anywhere. No `Object.freeze` (it costs a property
  access in the physics hot loop for no benefit here).
- Every id is a short lowercase string and is wire format. Comment saying so.
- 2-space indent, single quotes, semicolons.
- Comments explain *why* a number is what it is, and never restate the line above.
  Where a number is a pure guess with no evidence, say `// guess` on that line —
  `tools/balance.mjs` will find them later and it must be obvious which numbers were
  reasoned and which were invented.
- Keep it under 700 lines.

## When you are done

Run `node --check data.js` and `node tools/check.mjs` and make sure both pass. Then
print a short summary of anything in DESIGN.md that you could not express as data,
or that contradicted itself. Do not fix the design yourself — report it.

Write only `data.js`. Do not create or modify any other file.
