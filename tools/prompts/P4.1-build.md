## What build.js is

The fortress editor's **logic**, not its interface. It produces and validates
blueprints, which are plain data. It never creates a live world of its own — `sim.js` is
the only thing that turns a blueprint into bodies. No DOM, no canvas, no events.

It is imported by three hosts: the browser editor, the Cloudflare relay (which validates
and settles blueprints authoritatively in P6), and Node tools. So the determinism ban in
`ARCHITECTURE.md` §3 applies in full — `tools/check.mjs` will enforce it, and you should
add `build.js` to the list of files it checks for simulation purity.

## Editing model

A **draft** is the editable state: a list of placed pieces plus the budget. Keep it
plain and serialisable.

```js
export function makeDraft(opts)        // { budget, cards: [] }
export function place(draft, piece)    // returns { ok, reason }
export function removeAt(draft, x, y)
export function moveTo(draft, id, x, y)
export function rotate(draft, id, steps)
export function undo(draft) / redo(draft)
export function toBlueprint(draft)
export function fromBlueprint(blueprint, opts)
```

- Positions snap to `TUNE.gridSnap` (0.5). Rotation snaps to `TUNE.rotSnapDeg` (15°),
  stored as an integer 0–23 and converted with `fromDegrees` — **never** with
  trigonometry.
- Free rotation is allowed only by passing a unit `(c, s)` in directly, per §3.
- Undo must be real: keep a bounded history of drafts, not of inverse operations. An
  inverse-operation stack is where undo bugs live and the draft is small enough to copy.

## Budget

`BUDGET` in `data.js` gives the shape. `budget = base + perRound*(round-1) + perDeficit*roundsBehind`,
plus banked early-lock scrap. Costs come from `MATERIALS[m].cost * shape.area` and
`PIGS[p].cost`; the King is free and mandatory.

Cards change costs and unlock materials — `quarryman` makes stone 3, `heavy-industry`
makes iron 6 and unlimited, `iron-ration` unlocks iron with 2 per round, and so on.
Apply the card effects **from their declarative `effect` data**, not with a switch
statement per card id; the effects were authored as data specifically so this stays
table-driven.

`place` must refuse a piece the draft cannot afford, and refuse a material that is not
unlocked, each with a distinct machine-readable `reason`.

## Legality — `validate(draft or blueprint, opts)`

Returns `{ ok, errors: [{ code, message, pieceIds }] }`. Every rule reports **which
pieces** are at fault, because an editor that says "invalid" without pointing at anything
is unusable.

| code | rule |
| --- | --- |
| `out-of-bounds` | every piece inside the 24 × 16 plot |
| `overlap` | nothing intersecting at rest — use `maxPenetration` against `TUNE.slop` |
| `too-many-blocks` | at most `TUNE.maxBlocks` (120) |
| `king-count` | exactly one King Hog. The Decoy King does **not** satisfy this |
| `too-few-pigs` | at least `TUNE.minOtherPigs` (2) besides the King |
| `over-budget` | total cost within budget |
| `locked-material` | a material the draft has not unlocked |
| `buried-king` | burial depth above `TUNE.maxBurialDepth` (5) |

### Burial depth

From `TUNE.burialRayCount` (64) evenly spaced directions, cast a ray from outside the
plot toward the King and count the **distinct blocks** it crosses. Burial depth is the
**minimum** across all directions — the easiest way in. Above 5 the blueprint is
rejected.

Generate the 64 directions without trigonometry. A table of 64 `(c, s)` literals is
fine and is the obvious approach; say so in a comment so the next reader does not
"simplify" it into a `Math.cos` loop and silently break cross-engine replay.

## Settle test — `settleTest(blueprint, opts)`

Instantiate through `sim.js`, run `TUNE.blueprintSettleSeconds` (3) of fixed steps, and
return `{ ok, settled, movedPieces, deadPigs, settledBlueprint }`.

- Fails if anything moved more than a small tolerance, or if any pig died.
- On success it returns the **settled** blueprint, because DESIGN.md §6.2 says both
  players attack the settled state — nobody should win points from a tower falling over
  on its own.
- The relay runs this authoritatively in P6, so it must be pure and deterministic here.

## Encode and decode

`encode(blueprint)` to a compact string and `decode(string)` back, exactly.

Everything is small integers: shape index, material index, `x*2` and `y*2` on the 0.5
grid, rotation 0–23. Pack accordingly — a 120-block blueprint crosses the wire every
round and JSON would be several times larger than it needs to be. Include a version
byte. `decode` must reject malformed input with a reason rather than throwing, because
it will be fed hostile data by the relay.

## tools/editor-test.mjs

1. **Round trip:** 200 generated blueprints, seeded, through `encode` and `decode`,
   asserting exact equality. Report the average encoded size against the JSON size.
2. **Every rule rejects exactly what it should:** one crafted case per `code` above that
   fails only that rule, plus one valid blueprint that passes all of them. A rule that
   never fires in the test suite is not tested.
3. **`decode` rejects hostile input:** truncated, wrong version, out-of-range indices,
   absurd lengths. It must return a reason, never throw.
4. **The settle guarantee:** every blueprint that passes `validate` and `settleTest`
   must still be settled after a further 10 seconds. This is the property the whole build
   phase rests on.
5. **Budget:** placing beyond budget is refused; card effects change costs as authored.

Print measured values, exit non-zero on failure.
