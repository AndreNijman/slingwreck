Fix a drag-aim bug in `game.js`. It shows up as a flaky test, but the test is right and
the game is wrong.

## The measurement

`npm test` assertion 20, unchanged code, six runs idle then three runs under eight
busy CPU workers:

```
idle  x6      score  6,400; pigs dead 1/3   (all six identical)
loaded run 1  score  6,400; pigs dead 1/3
loaded run 2  score 11,800; pigs dead 2/3
loaded run 3  score  6,400; pigs dead 1/3
```

Same code, same viewport, same scripted drag, different shot. It passes either way today
only because the assertion is "at least one pig", so it is currently hiding its own
nondeterminism rather than reporting it.

## The diagnosis, and why it is a gameplay bug

The previous fix made the test wait for camera stability before pressing and convert its
world-space draw vector using a camera snapshot taken at press time. That was necessary
and it removed most of the variance. It did not remove all of it, because **the camera
moves during the drag**.

`P2.5b` specified that the aiming camera "zooms out smoothly if the drag is at full
stretch". So pulling the sling changes the camera, and if the draw vector is recomputed
each frame with `screenToWorld` against the *current* camera, the mapping shifts while
the pointer is still down. How far it shifts depends on how many frames elapsed, which
depends on machine load.

Now read that as a player rather than as a test: **you pull the sling back, the camera
zooms out, and your aim slides under your finger without you moving it.** The shot you
release is not the shot you were pointing at. That is a real feel bug and it is the same
bug.

## The fix

Anchor the aim to the pointer, not to the world.

- On press, record the pointer's screen position and the camera's scale at that instant.
- While dragging, compute the draw vector from the **screen-space delta** since the
  press, converted with the **scale captured at press time**, not the live one.
- The pouch then tracks the finger exactly, one-to-one, for the whole drag, no matter
  what the camera does. Zooming out becomes a purely visual affordance that shows more
  of the field, which is what it was for.

Keep the clamp to `TUNE.slingRadius` and keep launch opposite the draw.

Do the same for touch. Do not change the camera behaviour itself — the zoom-out is good
and stays.
