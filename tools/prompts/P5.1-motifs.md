skeleton, and `tools/level-export.mjs`. Read `docs/BUILD_PLAN.md` P5 including the
authoring correction, `build.js`, `sim.js`, `data.js`, and `docs/DESIGN.md` §5.

## First, a rule-set split that has to happen before any level exists

`validate` in `build.js` currently enforces the **Siege** rules, and several of them are
wrong for a campaign level:

- `king-count` — a campaign level has a King only in a boss level, not in all 52.
- `too-few-pigs` — an early tutorial level with one pig is correct design.
- `over-budget` — there is no budget in the campaign.
- `buried-king` — burial depth is an anti-turtle rule for a competitive build. An authored
  level is allowed to hide a pig deep, because the level designer also authored the ammo
  to get at it.

So take a `mode` — `'siege'` or `'campaign'` — and apply the rule set for it. Campaign
keeps `out-of-bounds`, `overlap`, `too-many-blocks` and `locked-material`, and drops the
four above. Siege behaviour must not change; assert both rule sets in
`tools/editor-test.mjs` so the split cannot silently drift.

Everything keeps `settleTest`. A level that collapses before the first shot is not a
difficulty choice, and that applies to both modes.

## The motif library

A motif is a **parameterised function returning blueprint pieces** at an offset. Not a
fixed lump — the point is that 52 levels are variations, so the parameters are where the
variety comes from.

Start with these, and add any the episodes need:

| motif | parameters worth having |
| --- | --- |
| `tower` | width, storeys, material per storey, whether it is capped |
| `bunker` | walls and a roof around a cavity, the cavity holding pigs |
| `bridge` | a span on two or more supports, with a gap underneath |
| `stack` | a plain column, the simplest thing that falls over |
| `keep` | a tower inside an outer wall, for boss levels |
| `scaffold` | thin posts and planks, deliberately fragile |

Rules for the library:

- A motif returns pieces in blueprint tuple form, positioned relative to an origin, so
  motifs compose by translation.
- Motifs must produce something that **stands on its own** — every motif gets an
  assertion that it passes `settleTest` at its default parameters and at its extremes.
  A motif that only stands sometimes will poison every level built from it and the bug
  will look like a level bug.
- No overlapping pieces within a motif, and a helper to check two motifs do not collide
  when composed, so a level author gets told at build time rather than by the validator.
- Snap everything to `TUNE.gridSnap` and use integer rotation steps only.

Put the library in `levels.js` if it stays small, or `motifs.js` if it does not — and if
you add a file, add it to `docs/FILE-PLAN.json` with a budget and a reason.

## levels.js skeleton

```js
export const EPISODES = [...]   // already in data.js; reference it, do not duplicate it
export const LEVELS = [ { id, episode, index, name, blueprint, bag, stars: [n, n, n] }, ... ]
```

Include **three real, finished levels of Episode 1** as a worked example of the whole
pipeline — motif composition, a hand-picked bag, star thresholds — so the pattern is
concrete before 49 more are written against it. Do not write all 52 in this task.

Star thresholds: leave them as `null` and have the linter report which levels are missing
them, rather than inventing numbers. They get set in P5.8 from bot play data. Do not
guess them.

## tools/level-export.mjs

Three jobs, one tool:

- `--lint` — every level through `validate(mode: 'campaign')` and `settleTest`. Reports
  per level: piece count, cost-equivalent, whether it settles, max movement during
  settle, and whether stars are set. **Exits non-zero** on any level that fails to
  validate or settle. This is the gate the P5 tasks lean on.
- `--export <id>` — print the encoded blueprint string for a level, to paste into the
  editor.
- `--import <id> <string>` — write a level's blueprint back from an edited string,
  rewriting the `levels.js` entry in place. This is the tuning loop; without it the
  editor cannot feed the campaign.

## Acceptance

1. `node tools/level-export.mjs --lint` passes on the three example levels and reports
   their measurements.
2. Every motif has a settle assertion at default and extreme parameters, and they pass.
3. `node tools/editor-test.mjs` — including new assertions that the campaign and siege
   rule sets differ in exactly the four rules named above, and that Siege is unchanged.
4. `node tools/check.mjs`, `node tools/sim-test.mjs`, `npm test`, `npm run test:audio`.
5. Export then import one level and assert the blueprint is byte-identical, since P5's
   whole tuning loop depends on that round trip.
